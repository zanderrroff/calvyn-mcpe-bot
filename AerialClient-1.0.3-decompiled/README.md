## Как это получено

1. Скачан ассет `AerialClient.dll` релиза v1.0.3.
2. Разбор PE через `pefile` (`tools/pe_report.py`) — заголовки, импорты,
   ресурсы, строки, энтропия секций.
3. Импорт и полный автоанализ в Ghidra 12.1.2 (headless), 84 секунды.
4. `RecoverClassesFromRTTIScript` — восстановление классов из RTTI:
   31 класс, 119 методов, 114 виртуальных функций.
5. `tools/ExportDecompilation.java` — декомпиляция каждой функции и выгрузка
   в файлы, вместе с типами, символами, строками и картой памяти.

Воспроизведение:

```
analyzeHeadless <проект> AerialClient -import AerialClient.dll
analyzeHeadless <проект> AerialClient -process AerialClient.dll -noanalysis \
    -preScript RecoverClassesFromRTTIScript.java
analyzeHeadless <проект> AerialClient -process AerialClient.dll -noanalysis \
    -scriptPath tools -postScript ExportDecompilation.java <выходной каталог>
```

## О комментариях

Комментарии в коде отключены на уровне декомпилятора (`WARN`, `PLATE`, `EOL`,
`PRE`, `POST`, `Head`) и дополнительно вырезаны разборщиком, который не трогает
строковые литералы. В `src/` и `include/` комментариев нет.

Единственное место, где встречается последовательность `//` — строковые литералы
с исходником HLSL-шейдеров: это оригинальный текст шейдеров из бинарника, он
оставлен без изменений, иначе восстановленный материал перестал бы совпадать
с содержимым файла. Те же шейдеры отдельно лежат в `shaders/`.

## Что нужно знать о результате

- Это декомпиляция машинного кода в C. Восстановить из бинарника без отладочных
  символов исходный C++-проект, который соберётся обратно, невозможно —
  ни один инструмент этого не делает. Имена локальных переменных, шаблоны,
  инлайненные функции и границы классов в бинарнике не сохраняются.
- Имена классов и модулей восстановлены из дескрипторов RTTI, поэтому они
  настоящие, авторские. Имена функций вида `FUN_180xxxxxx` — синтетические,
  адресные.
- Около 21.5% функций (837 из 3895) собраны с уплощением потока управления:
  тело функции превращено в цикл-диспетчер с XOR-состоянием. Логика в таком
  коде читается, но структура не соответствует исходной.
- Пользовательские строки (названия модулей, тексты интерфейса, пути настроек)
  зашифрованы на этапе компиляции и расшифровываются в рантайме. В `.data`
  из-за этого 196 КБ данных с энтропией ~7.7. В открытом виде остались только
  строки логов, имена хуков, шейдеры и служебные строки CRT.
